# Development Roadmap & Verification Gates | Unity Rework

> 설계 완성도와 코드 완료도를 혼동하지 않는다. 단계별 PR의 목표는 "파일이 있다"가 아니라 "게임에서 실제로 동작하고 회귀 테스트를 통과한다"다. 과거 Godot PR/이슈는 현재 Unity 작업 완료 근거가 아니다.

**진행 순서 원칙:** P2 저장 기본 계약을 P3 실제 영구 보상에 앞서 완료. P4 전체 27종은 P3 6~8종 임시 검증을 토대로 확장. P8 미확정 정책은 결정 전에 P0~P1 구현을 막지 않되, **영구 자산 소실/지급과 관련된 부분은 실제 커밋 연결을 막는다**.

## 테스트 피라미드

**1. EditMode 테스트 (빠름)**
- 플레이어 기본 수치/저항·관통·치명타/광역+DoT 33% 흡혈.
- 올바른 발동 연쇄 허용/순환만 차단, 무한 스택 집약 처리.
- 단독 27종 플러그인 카탈로그 검증 및 개별 레벨 상한/효과/데이터 무결성.
- 카드 슬롯 3개 등급 독립, 리롤 선택 슬롯만 변경, 5회 미등장 화면 단위, 슬롯 재현성, 고갈 후보 처리(승인 후).
- 5개 하드웨어 난이도 보장, 환경 변이 분포, 시드 100개에서 연결 경로(샘플 수 초안).
- 3→2→1→0→최종파기, 기존 XP/DB 보존, 희귀 레어 원본/추가 수령 한 트랜잭션.
- synthetic save 권한 실패/강제 종료/중복 영수증/future schema/ACK 유실/체크섬·백업 복구.

**2. PlayMode 테스트 (실제 Unity 런타임)**
- 카메라 룩어헤드 목표/최대 거리/지도 경계/월드 조준/커서 DPI.
- 이동/Space 대시·적 AI·탄환·환경 함정·보스 패턴 연계.
- UI 카드 선택→실제 전투 재계산→저장 결과 반영/실패 안전 정지.
- CPU 진입→보스→정화→철수→백신 성장/플러그인 DB→재실행/사망→영구 복구.
- GPU/RAM/SSD/HDD를 임의 순서로 연속 공략, 맵 스타일뿐 아니라 공격·목표가 서로 다름.

**3. Windows 수동 검수 (CI로 대체 불가)**
- Unity Hub 새로 열기/컴파일/프로젝트 import, 장치 실제 GPU와 드라이버 정보 기록.
- 게임 1080p 창/전체화면/ALT+TAB, Windows DPI 100/125/150/200, 화면비/커서/리바인딩.
- 실제 음악·효과음/마스터·SFX 음량, 이어폰·스피커 장치 전환.
- CPU 8~12분, 5개 전체 40~60분, 1개 철수, 4번째 사망까지 실제 플레이 기록.
- 플레이 중 작업 관리자 kill/디스크 권한 실패/게임 리스타트의 저장 경계 테스트. **실제 사용자 파일이 아닌 테스트용 게임 슬롯만**.
- 퍼포먼스: 30초 워밍업 후 프레임타임 p50/p95/p99·GC alloc·드로우콜, 심한 연쇄·많은 적 스폰 구간 분리 측정 [세부 시험시간 초안].

## 저장/QA 차단 정책

- 한 단계에서 PR/CI 체크가 성공했어도 UI 스크린샷과 Windows 플레이가 없다면 `실기기 미검증`.
- 보상/파기/DB 소실 관련 Open Question이 사용자 승인 전이면 **그 정책을 영구 저장에 연결하지 않는다**.
- 크래시 발생 뒤 게임 자체가 임의로 회복/포기/복제를 소모하지 않는다. 사용자가 고르는 중단 처리 정책이 승인될 때까지 safe-state 표시.
- 오류 문자열을 감춘 상태로 데모만 보여주지 않는다. `runId/tick/seed/receiptId/scene/exception`을 개인정보 없는 로컬 로그에 남긴다.
- 이전 Python 코드/기획 원본을 비파괴로 남긴다. Unity build로 원본 세이브 경로가 영향을 받지 않는지 검증.
