## 1. 제품 개요

**[확정]** Neon Void는 **감염된 컴퓨터 내부에서 백신이 바이러스를 정화하는 싱글플레이 PC 3D 탑다운 액션 로그라이트**다. 주인공은 인체가 아니라 '백신 프로그램'이며, 무대는 메인보드·CPU·GPU·RAM·SSD·HDD를 추상화한 하드웨어 세계다. 디펜더 허브를 직접 이동하고 여러 하드웨어를 원하는 순서대로 공략한다. 빠른 전투, 조합 폭발, 계산된 철수, 영구 백신 성장 및 복제 상실의 긴장감이 축이다.

**장르 문장:** `탑다운 3D 액션 + 자동사격/3액티브 스킬 + 절차적 5하드웨어 탐험 + 플러그인 빌드 로그라이트 + 백신 영구 성장/최종 파기`.

**[초안] 포지셔닝:** 1회 하드웨어 정화 평균 8~12분, 한 개 정화 후 짧게 철수 또는 5개 연속 도전(대략 40~60분). 강제 5개 완주가 아닌 '위험/보상 결정'을 플레이어에게 준다. 목표 플레이 시간은 실제 데이터로 검증해야 하며 튜토리얼 시간을 별도 측정한다.

**[초안] 첫 배포:** Windows PC/키보드·마우스/싱글플레이/오프라인 우선, 16:9 기본, 창/전체화면, 한국어 UI 기준. Linux·영어 번역·컨트롤러·Steam Cloud는 추가 범위이며 확정 출시 요구가 아니다.

**이 프로젝트가 아닌 것:** Godot 재포팅; Python의 4개 OS 구역 그대로 3D화; 전체 게임을 GUI 메뉴 하나에서 실행하는 게임; 외부 유명 게임 시스템/아트를 그대로 복제하는 게임.

## 2. 게임을 구성하는 네 가지 루프

### 2.1 백신(장기) 루프 [확정]

백신 선택 또는 생성 → 3D **디펜더 허브** → 영구 능력치 포인트 투자/무료 재분배 → 플러그인 DB에 보관된 아이템을 출전 소지 목록으로 **이동** → 장착 스킬 3개 확인 → 의뢰 시작 → 철수·사망 정산 → 허브 또는 최종 파기 후 백신 선택.

- 백신 장기 레벨/XP는 의뢰 경계를 넘어 유지된다. 새 의뢰가 시작돼도 이 값은 초기화하지 않는다.
- 출전 소지 플러그인은 사망 시 소실되므로 '들고 간 영구 자산'도 위험 자산이다. DB에 남긴 학습 플러그인은 1~3회 사망에서 보존된다.
- 백신은 3번 복제 부활할 수 있고 **4번째 사망에서 최종 파기**된다. 복제 횟수 복원 수단은 없다.

### 2.2 의뢰(런) 루프 [확정]

허브에서 의뢰 시작 → 의뢰 고유 ID/시드 → 메인보드 도착, 소수의 도입 적과 조작 확인 → 5개 하드웨어 선택(자유 순서) → 구역별 절차 맵/목표/전투/보상/보스 → 정화 → 같은 의뢰에서 다른 미정화 하드웨어 도전 또는 철수 → 보상 정산 및 학습 플러그인 최대 2개 선택 → 허브 복귀.

- 매 의뢰 **의뢰 레벨 Lv.1**로 시작한다. 의뢰 레벨은 백신 장기 레벨과 별개다.
- 하드웨어 난이도는 의뢰 시작 때 무작위 지정되며 **5개 중 최소 1개는 쉬움**으로 보장한다.
- 5하드웨어(CPU/GPU/RAM/SSD/HDD)는 순서 강제 없음. 감염·절차적 지형·목표 성격·보스 및 플레이 리듬이 서로 달라야 한다.
- **1개 이상 정화한 뒤** 정화한 구역의 철수 지점으로 철수 가능. 5개 모두 정화는 필수가 아니지만 추가 보너스가 있다.
- 사망은 **해당 의뢰 실패**이며 실패 의뢰 전투를 그대로 재시작하지 않는다. 새로운 의뢰는 새 맵/새 적이 생성된다.

### 2.3 전투 루프 [확정]

이동(WASD), 커서 기반 조준, 자동사격, **이동 방향 Space 대시**, 별도 **액티브 스킬 최대 3개** (마나/쿨타임), 피격/상태이상/막기/회피/연쇄 공격 → 적 처치 및 목표 해결 → 의뢰 XP/플러그인 선택 → 강화된 빌드로 다음 교전.

- **60Hz 논리 시뮬레이션**. 프레임 수가 피해량·연쇄 순서·목표 완료를 바꾸면 실패.
- 플레이어와 적은 공통 능력치 및 효과 처리 구조를 공유. 물리/마법/고정 피해, AD/AP, 관통·저항, 치명타, 흡혈, 강인함, 보호막, 버프·디버프.
- 정상적인 다단계 효과 연쇄는 허용하고 **같은 발동 경로 안의 순환만 차단**한다. 단순 전역 횟수 제한으로 정상 빌드를 죽이지 않는다.

### 2.4 선택 보상 루프 [확정]

의뢰 레벨업, 하드웨어 정화, 맵 이벤트 시 **3장의 플러그인 카드** → 1장 선택. 각 슬롯의 등급을 독립 추첨하고 **원하는 카드 1장만** (등급과 플러그인 종류를 모두) 재추첨할 수 있다. 의뢰 시작 기본 리롤 3회, 추가 획득 가능. 플러그인 중복 획득 시 해당 플러그인 레벨업. 최대 레벨 후보 제외.

- 등급: **일반 / 레어 / 전설 / 신화**. 문서화된 원안 콘텐츠는 일반 17 + 레어 7 + 전설 3 = 27종이며 신화의 구체적 종류는 아직 미확정이다.
- 전설 이상 카드가 **플러그인 보상 화면 기준** 5회 연속 등장하지 않으면 이후 확률 보정 시작(카드 수 기준 아님).
- 난이도, 정화 수, 행운에 따라 등급 확률 변동. 정확한 계산식/확률/리셋 기준은 아직 미확정.
- 1회 의뢰에서 얻은 **일반·레어** 중 성공 철수 뒤 **최대 2개를 학습**. 전설·신화는 영구 학습 불가.

## 3. 플레이 가능한 월드 구조

**[확정]** 허브와 메인보드는 단순 메뉴 목록이 아닌 **실제 3D 공간**이다. 허브에는 의뢰/백신 성장/플러그인 데이터베이스/스킬 장착 터미널이 있다. 메인보드에서는 하드웨어를 지형적으로 식별하고 접근할 수 있어야 한다. 3D 모델을 사용하더라도 **상부에서 내려다보는 탑다운 시점과 평면 XZ 이동**을 기본으로 한다.

**[초안]** 허브에서 주요 기능까지 10~20초 내 접근 또는 단축 UI. 보상 선택·정교한 수치 비교는 2D 오버레이가 담당한다. 장황한 터미널 이동이 성장을 방해하지 않도록 직접 이동과 빠른 UI를 혼합한다.

**[확정]** 카메라는 커서와 플레이어 위치의 중간(**룩어헤드 50% 목표**)을 따르되 오프셋 최대 제한/부드러운 보간, 플레이어 화면 이탈 방지, 맵 경계 준수. 실제 마우스 조준은 3D 지면과의 교차점으로 계산하고 카메라 보간과 독립시킨다.

**[초안]** 월드 1 Unity unit = 1m 개념으로 새 게임을 단순화한다. Python 1280×720 논리 화면/px 이동·대시 값은 플레이 감각 검증 참고값이지 새 3D의 자동 환산 공식이 아니다.

## 4. 난이도와 환경

**[확정]** 각 하드웨어는 개별 난이도와 환경 상태를 가지며, 최소 한 곳에 쉬움이 항상 존재한다. 환경은 `이상없음`, `변이발생 1~5단계`, `스택오버플로우(적 증가)`, `터널감염(미학습 소지 플러그인 1~2개 비활성/역효과)`, `확산(맵 확대)`, `초기상태(맵 축소)`를 포함한다. 터널감염은 **학습된 플러그인 제외**. 같은 환경에 다시 도전할수록 변이발생이 **등장했을 때의 상위 단계 비율**이 커질 수 있지만 변이발생 자체 확률 상승은 필수 아님.

**[미확정]** 환경 동시 적용 여부, 무작위 난이도 분포, 맵 재진입, 외부 진입 경로, 쉬움 구간의 정확한 보상 배율. `01_WORLD_AND_CONTENT.md`의 표는 개발 시작용 제안이며 데이터로 분리한다.

## 5. 능력치·상태·스킬

**[확정된 초기값]** AD=5, AP=0, 치명타 피해 120%, 탄환속도 배율 1.0, 행운 0%, 탄환 크기 정수 10, 적중시 흡혈 0%, 모든 피해 흡혈 0%. 최대 마나/초당 자동 회복 **능력치 자체는 확정**, 숫자는 초안이다. 발사속도·스킬 가속의 무한대/쿨타임 0방지는 확정 방향.

**[초안 값]** HP100, 이동속도 5u/s, 발사속도 2발/s, 최대MP100, MP재생5/s, 기본 방어력0. 초안 저항과 쿨타임 공식은 `02_COMBAT_AND_STATS.md`에 명시.

**[확정]** 광역 또는 지속 피해의 '모든 피해 흡혈'은 **33% 효율**, 광역+지속이 겹쳐도 33% (이중 33% 적용 금지). 사용자는 기본 대시 1개와 마나를 쓰는 액티브 스킬 3슬롯을 가진다. 습득 스킬은 백신 파기까지 보유; 임무 중 **새로 습득한 스킬**은 그때에 한해서 장착 교체 가능.

## 6. 성장과 사망·DB

**[확정]** 백신 경험치는 의뢰 목표와 정화에서 획득하며 영구 레벨업 시 영구 능력치 포인트 제공. 허브 무료 재분배. 미정산 경험치/포인트는 사망 시 **진행도에 따라 20~70%만 정산**(구체 계산식은 초안). 반면 이미 성공적으로 확정된 영구 XP/포인트는 복제 사망에서 잃지 않는다.

**[확정]** 학습한 일반/레어 플러그인 최대 2개 신규 학습, 레벨 보존, DB 보관 무제한, 출전 수 제한 없음, DB → 출전 이동 시 **DB 원본 제거**, 사망하면 출전분 소실, 성공 귀환해도 자동 DB 보관 없음. 영구 스킬 및 DB는 1~3회 사망 후 남지만 4회 사망에 해당 백신 성장 자산 일괄 파기. 전역 게임 설정은 유지.

**[미확정]** 기존 학습 출전 플러그인을 성공 귀환 후 회수하는 처리와 '신규 학습 2개' 한도 관계, DB에 같은 효과의 여러 인스턴스 허용 정책, 사용자 요청 없는 의뢰 강제 종료 이후 재개/포기 규칙. 영구 지급/삭제 결과가 바뀌므로 임의 확정 금지.

## 7. 게임성 개선 원칙

1. **5개 구역은 실제 플레이 선택을 바꿔야 한다.** 색만 바꾼 던전, 동일 보스/환경 복붙 금지. 각 구역은 최소 대표 목표 2~3개, 고유 위험, 적 조합, 독립 보스 패턴을 갖는 방향 [초안].
2. **위험은 읽혀야 한다.** 보스 텔레그래프, 상태이상, 터널감염, 무적·보호막, 파기 위험은 사전 예고와 실제 판정 일치.
3. **선택은 비교 가능해야 한다.** 카드의 현재·다음 Lv 변화, 장착 빌드와 시너지, 철수 시 지금 받을 보상/추가 정화 위험을 화면에 제시.
4. **빌드는 시원하게 강해지되 읽히게 연출한다.** 27개 이상 플러그인 무제한 동시 보유에도 연쇄를 고의로 억제하지 말고 판정/표현을 독립 최적화.
5. **메인보드는 길찾기 게임이 아니다.** 이동 자체가 재미를 부여하되, 같은 허브/도입전을 매번 지루하게 반복하지 않도록 빠른 이동·재도전 UX [초안].
6. **런 실패는 납득돼야 한다.** 데이터 손상/크래시/의뢰 포기는 4번째 사망으로 취급하지 않는다. 정확한 저장 상태와 위험 정보 우선.
7. **소프트웨어→플러그인 명칭 정리.** 과거 Python 저장 키는 무단 변경 금지, 신규 Unity UI 텍스트에서는 플러그인으로 일관.

**완료 판정:** '씬이 열린다'가 아니라 게임 내 실제 연결 여부, 저장 정확성, 회귀 자동검증, Windows 실사용 기기 플레이, 목표 8~12분 측정을 갖춰야 한다.

## 9. 가장 중요한 미확정 사항

자세한 항목/우선순위는 `08_DECISIONS_AND_CONFLICTS.md`. 특히 **의뢰 중 게임 종료 처리**, **플러그인 DB 회수 계약**, **플러그인 등급 수치/천장**, **레이저/부메랑 복합 변형**, **스킬 3칸 키/스킬 목록**, **보호막·흡혈 세부 순서**, **보스/정화 중간 정산 및 재방문 규칙**을 놓치지 않는다. 게임을 구현할 수 없게 방치하는 대신 데이터/전략 인터페이스로 분리하고 위험한 영구 기록은 잠근다.
