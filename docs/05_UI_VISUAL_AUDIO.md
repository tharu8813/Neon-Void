# UI/UX, Art Direction, Animation, VFX & Audio | v2.0

> 이전의 GDD SVG 6개 (`docs/assets/gdd/`)는 참고 시안일 뿐 최종 승인된 UI/에셋 아님. Python의 네온 감성과 탑다운 플레이의 정보 가독성을 유지하면서 **새 Unity 3D 게임용 디자인 시스템**을 만든다. 아래 색·폰트·모션·배치는 **[초안]**.

## 1. 화면의 기본 철학

**우선순위:** (1) 생존과 위험 신호 (2) 조준·스킬·대시 (3) 목표/정화/철수 (4) 레벨과 플러그인 강화 (5) 장식 네온·글리치. UI가 화려해도 정지/속박/피격/보스 공격의 판정을 가리면 실패.

**[확정]** 3D 허브를 직접 이동, 3D 탑다운 전투, 마우스 조준, 3장 카드/개별 새로고침, 백신/의뢰 레벨 분리, 출전 소지·DB 구분, 복제 0회에서 다음 사망 파기, 정화 1개 후 철수. **[초안]** 레이아웃은 1280×720 논리 화면을 디자인 기준으로 삼되 실제 16:9·4:3·21:9 및 Windows 100~200% DPI에서 리플로우.

## 2. 화면 구조와 플레이어 행동

| 화면 | 기본 구성/정보 | 주요 액션 | 성공/실패/엣지 |
|---|---|---|---|
| **백신 선택** | 생성된 슬롯·레벨·XP·복제 잔여·DB 개수·마지막 플레이 | 새 백신, 선택, 옵션 | 빈 슬롯·파기된 백신·저장 오류 분리 |
| **디펜더 허브** | 3D 임무 포털/능력치/DB/스킬 터미널, 대화/상호작용 힌트 | 이동, F 상호작용, 빠른 관리 메뉴 | 접근 불가 터미널·입력 포커스 |
| **영구 스탯** | 보유 포인트, 구매 전후 값, 실제 방어감소율, 무료 재분배 | 투자/전체 재분배/취소 | 저장 전 값 확정 표시 금지 |
| **DB** | 왼쪽 출전 소지, 오른쪽 보관 DB, 레벨·사망 위험 | 꺼내기/넣기, 아이템 상세 | 같은 인스턴스 양쪽 중복 불가 |
| **스킬 설정** | 백신이 학습한 스킬/3슬롯, MP/CD/태그 설명 | 장착/바꾸기, 키 확인 | 미학습·중복·저장 거부 |
| **메인보드** | 5개 하드웨어 가독성 있는 진입점, 난이도/환경/정화 | 자유 순서 선택·현재 의뢰 정보 | 최소 쉬움 1개, '접근 불가' 숨기지 않음 |
| **전투 HUD** | HP·MP, 스킬 1~3 CD, 대시, 의뢰 Lv/XP, 상태이상, 목표/보스 HP | 실시간 전투, 상세 빌드 보기 | 무결성 공격·속박·마나 부족·입력 불가 피드백 |
| **플러그인 선택** | **3개 카드**, 개별 등급/현재Lv→선택후Lv/효과, 개별 리롤, 잔여 횟수 | 카드 한 장 고르기/한 장만 리롤 | 저장 중 입력 잠금, 후보고갈 정책 [미확정] |
| **구역 정화** | 달성 목표/획득 보상, 다음 하드웨어·철수 지도 | 의뢰 지속 또는 정화 지점 철수 | 적어도 1개 정화 후 철수 허용 |
| **철수 정산** | 영구 XP/포인트, 학습 가능 일반·레어 최대2개, DB 안내 | 0~2개 학습 확정 후 허브 | 전설·신화 학습 금지, 영수증 확인 전 승리 완료 금지 |
| **사망/파기** | 이번 의뢰 손실·보존 XP, 복제 잔여, 최종 파기 위험 | 결과 확인·백신 선택 | 3번째 사망 잔여 0 ≠ 파기, 4번째만 파기 |
| **설정/오류 복구** | 키·음량·그래픽·접근성 / 저장 상태·복구 로그 | 재설정·복구 요청 | 크래시를 사망 처리하지 않음 |

**UI 실수 방지:** 인게임 전투 도중 터미널/카드가 열리면 조준·대시 입력은 유효하지 않아야 한다. 단, 시스템 메뉴 접근까지 '정지' 상태이상으로 차단하지 않는다.

## 3. 보상 카드 상세 (불편한 UI를 피하는 기준)

- 각 카드 상단: `등급`, 플러그인 아이콘, 임시/영구 여부. 중앙: 단 한 문장으로 주효과, 현재 레벨/다음 레벨의 **수치 비교**, 하단: `단일 카드 리롤` 버튼.
- 공통 헤더: 어떤 이유로 보상 화면이 발생했는지(의뢰 Lv/구역 정화/이벤트), `현재 리롤 2/3`, 현재 의뢰 레벨/플러그인 개수.
- 카드에서 미확정 스탯 값이 등장해도 '미확정' 표시를 일반 플레이어에게 뿌리지 않는다. 대신 개발 빌드에서는 `Prototype` 메타를 확인하고 출시 전 결정 미비를 차단한다.
- 레어·전설·신화는 일관된 색·테두리·모양. 색각 이상 사용자는 텍스트/도형으로도 구분.
- 고급/자세한 정보는 펼침 또는 상세 키로 제공하고 기본 뷰는 한눈에 읽힌다. 무의미한 설명 문단·패널 장식 과다 금지.
- 저장 중 로딩 스피너는 상태 정확성을 반영. 비동기 보상이 확정 전에는 레벨/성장 재계산·VFX 축하 연출 선실행 금지.

## 4. 시각 시스템 [초안]

| 디자인 토큰 | 샘플 값 | 의도 |
|---|---|---|
| Background | `#080E20` | 깊은 전산 공간 |
| Panel | `#121D39` | 반투명 HUD 표면 |
| Primary | `#7DEAFF` | 백신·조작 가능 항목 |
| Danger | `#F36BAA` | 감염/피격/위험 |
| Rare | `#BD8BFA` | 레어 |
| Legendary | `#FFD37A` | 전설 |
| Mythic | [초안 필요] | 전설과 색뿐 아니라 문양/움직임 차별 |
| Cleanse | `#7FECB5` | 정화·저장 승인 |
| Text | `#EBF4FF` | 주요 읽기 텍스트 |

- 지역 색은 **보조 테마**, 공통 피해·정화·경고 색의 의미는 지역이 바뀌어도 같다.
- 플레이어 백신은 완성된 아트 이전에도 적/아군 구분과 회전·이동·피격/무적 상태가 즉시 읽히는 실루엣.
- 3D 지형은 공용 모듈형 기판/금속/광선 채널을 사용하되, 5구역 각각 대표 오브젝트(히트싱크, 렌더 큐, 메모리 타워, IO 레일, 물리 디스크)를 달리한다.
- 네온 Bloom은 '규칙을 장식하는 계층'이지 위험 표시의 유일한 방식이 아니다. 색 대비 및 작은 UI 텍스트의 AA/GPU 프레임 비용 점검.

## 5. 애니메이션 / VFX [초안]

**자주 보이는 핵심 8장면**: (a) 백신 부팅·허브 진입 (b) 플레이어 무기 회전·자동 사격 반동 (c) 대시 후 짧은 잔상 (d) 명중 스파크·피해 타입 (e) 레이저/부메랑/연쇄번개/해체 DoT 발동 궤적 (f) 보스 위험 경고→발동→충돌 (g) 하드웨어 정화와 철수 게이트 (h) 최종 파기→백신 슬롯 전환.

- **타격 판정은 전투 시스템이 이미 확정한 결과를 읽는다.** VFX 시스템이 직접 HP/보상·플러그인 확률 변경 금지.
- 이펙트 종류를 너무 많이 늘리지 않고 `생성(발광)→공격 준비(축적)→발동(확장)→소멸` 모션 문법으로 통일. 파티클 재사용/pooling/GPU 인스턴싱 가능.
- 폭발·레이저·장판은 충돌 영역과 화면 효과 표시가 다를 수 있으나 **위험 경계선은 실제 피격 영역과 정확히 맞춘다**.
- 실루엣·바닥 경고·보스 HP가 파티클로 가려지면 입체 광원보다 판정 우선.
- 물체가 많아질 때는 GPU 파티클/배칭/LOD/Decal 수량을 줄이되 **실제 피격 횟수는 변동시키지 않는다**.

### [초안] 3단계 이펙트 설정

| 옵션 | 절전 | 균형 | 최상 |
|---|---|---|---|
| Bloom·후처리 | 최소 | 중간 | 고급 |
| 잔상·장식 파티클 | 일부 생략 | 기본 | 추가 |
| 위험 선/공격 판정 시각화 | 동일 | 동일 | 동일 |
| 실제 피해/AI/XP/플러그인 | 동일 | 동일 | 동일 |

## 6. 오디오 [초안]

사운드는 단순 클릭음 모음이 아니라 **시스템 내부 세계의 신호**로 다룬다. 강한 충격(피격·대시·보스 경고), 레벨업/카드/학습, 허브 안정, CPU 클럭, GPU 신호, RAM 딜레이, SSD 스트리밍, HDD 회전 사운드의 서로 다른 표정이 필요.

- 위험 공격은 **음향 없이도 피할 수 있어야 한다**. 색각·청각 사용자에게 시각 예고, 모션, 모양 제공.
- BGM·효과음·UI·마스터 볼륨 분리, 음소거 저장/복구, 창 비활성화/Alt+Tab 뒤 복귀, 동시 발음 제한과 오디오 풀 검증.
- 외부 SFX/BGM 사용 허용하되 원곡 무단 샘플링/배포권 불명확 파일 금지. Unity AudioSource부터 시작, FMOD/Wwise는 필요성/라이선스·빌드 검증 시 도입 후보.

## 7. 접근성/조작 QA [개발 필수]

- 창 모드/전체화면/Alt+Tab/다중 DPI·마우스 좌표 변환 100/125/150/200%를 별도 확인.
- `1280×720`, `1920×1080`, `2560×1440`, 울트라와이드, 4:3에서 UI가 화면 밖으로 잘리지 않는지 검증.
- 리바인딩·키 중복 확인과 스킬 Q/E/R vs 과거 R 동작 충돌 방지.
- 개별 화면 흔들림·카메라 이동 강도·플래시 제한·파티클 경감·피해 숫자 크기 옵션 [초안].
- 전투에서 UI 보기 전후 커서 잠김/해제, 게임 패드 미지원 경로, 스킬을 눌렀지만 MP 부족인지 CC인지 다른 이유인지 구분 가능.

## 8. UI/VFX 완료 정의

기능적으로 정보가 연결돼야 한다. 실시간 현재 HP/MP·상태이상 스택·목표·보스 HP·리롤 남은 횟수·실제 DB 소유 위치·복제 위험 등이 **게임 상태에서 갱신**되고, 하드코딩된 숫자 시연 화면이 아니어야 한다. Windows 실기기에서 조준·커서·DPI·이펙트/음향·GPU 성능·키 변경까지 확인한 후에만 완료.
