## 1. 최신 소스 기반 현재 상태 (시작점)

- `main` 기본: launcher 선택 화면 → REWORK 일반 `scenes/rework/integration/rework_main.tscn`, 독립 REWORK QA `rework_qa_boot.tscn`, 이전 Godot `scenes/main.tscn`. `python/**` 보존. 모드별 저장 슬롯 **혼합 금지**.
- 실제 파일 기준 B 스킬 레지스트리 **9종 BALANCE_DRAFT**, C 플러그인 카탈로그 **27종(일반 17/레어 7/전설 3)**, D 하드웨어 **5개** 코드와 E 버전/영수증 저장을 보유. 이는 실제 게임 완성도/전수 실전 검수 완료라는 뜻이 아니다. 신화 플러그인·수치와 일부 복구 정책은 **미확정**.
- D 구역은 서로 다른 목표·환경/보스 역할 초안이 있지만 지형이 공통 절차 생성기 계열이며 B 일반 적/보스 메시가 범용 원형/캡슐이다. `D-procedural-v1`의 기존 시드 재현성을 훼손해서는 안 된다.

- CI/headless 통과는 실물 Windows 음성, GPU 프레임타임, 모니터/DPI, 장시간 게임 감각을 입증하지 않는다. [#143](https://github.com/tharu8813/Neon-Void/issues/143), [#63](https://github.com/tharu8813/Neon-Void/issues/63), [#77](https://github.com/tharu8813/Neon-Void/issues/77) 추적.

## 2. 목표 게임과 절대 보존 규칙

**출시 목표:** 별도 합성 QA 보상이 없는 새 백신으로 3D 허브에서 시작 → 직접 하드웨어 자유 선택 → 구역별 8–12분 목표 탐색/전투/보스 → 개별 정화 → 1구역 이상 성공 철수/5구역 추가 보상 → 영구 성장/플러그인 DB/스킬 장착 → 다음 의뢰를 반복할 수 있는 게임. 3회 복제 가능, 4번째 사망 백신 파기. 반복 플레이 때 빌드·지역·위험·보상 선택이 달라져야 한다.

- 원본 `python/**`, 기존 Godot 모드, `docs/**` 기존 내용, 다섯 기존 JSON, 다른 슬롯의 플레이어 데이터 삭제·초기화·자동 변환 금지. 필요하면 명시적 opt-in copy-first migration.
- 저장은 E만 최종 권위: 모든 맵 시드/카드/정화/성장/학습/죽음은 E 원자적 ACK 후 사용자에게 확정. 중복 영수증 재지급 금지, 저장 불확실 시 fail-closed + 읽기 전용 복구 진단.
- GDD의 **[확정] / [초안 v0.1] / [미확정]** 구별. 미확정 신화 플러그인, 수치, 조합 규칙, 이어하기/포기 정책은 사용자 승인 없이 공식 명세라 부르지 않는다. 테스트용 기본값은 데이터 구동·버전 명시.
- B owns `scripts/rework/combat/**`, `skills/**`; C `plugins/**`, `data/rework/plugins/**`; D `world/**`, `camera/**`, `scenes/rework/world/**`; E `progression/**`, `persistence/**`; A `integration/**`, `ui/**`, 공통 docs/workflows/root. 전용 tests도 동일 소유.
- 렌더/사운드 RNG와 전투/보상 RNG 분리. 룩어헤드·조준/대시·텔레그래프의 픽셀 판정 일치. 성능 옵션이 피해량·60Hz 판정을 바꾸지 못한다.

## 4. 작업·병합 프로토콜 (A 게이트 필수)

1. **매 단계 시작:** A가 최신 `main` SHA에서 `integration/rework-sNN-...` 브랜치를 생성하고, 해당 단계 요구·소유 이슈·PR 베이스·테스트 체크리스트를 고정한다. S01: [`integration/rework-s01-playable-core-20261118`](https://github.com/tharu8813/Neon-Void/tree/integration/rework-s01-playable-core-20261118).
