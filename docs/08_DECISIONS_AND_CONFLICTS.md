## 2. 충돌 및 정리 (중요도 높은 순)

| 번호 | 과거 문서·구현의 차이 | 현재 판단/행동 |
|---|---|---|
| C01 | Python/Godot 기존 **4개 OS 섹터(CPU CORE/MEMORY/STORAGE/NETWORK)** vs 신규 **5하드웨어(CPU/GPU/RAM/SSD/HDD)** | **5하드웨어가 [확정] 우선**. 구 섹터 UI/맵을 이름만 바꿔 재사용 금지 |

| C05 | 2D 원본의 플레이어 화면 중앙 추적 vs GDD **50% 커서 룩어헤드** | 최신 [확정] 50% 룩어헤드 + 상한/화면 밖 이탈 방지 |
| C06 | 2D 322px/s·940px/s·0.145s 대시·0.32s 무적 vs 새 3D 속도 단위 미정 | 레거시 수치는 감각 참고. **단위 변환·대시 무적은 [미확정]**으로 남김 |
| C07 | 27 플러그인이라는 표현 vs 일반17/레어7/전설3 + 신화 추가 | 현재 **원안 27종**만 상세 목록 존재. 신화는 존재 확정/개별 효과 미확정; 27에 임의 신화 포함 금지 |
| C08 | 3회 복제 vs '3회 사망하면 파기' 식 해석 | **3번 사망 후 부활, 4번째 사망 최종 파기**가 정확한 [확정] |
| C09 | 백신 영구 Lv vs 의뢰 임시 Lv | **두 레벨 분리**, 의뢰 Lv.1 시작. 레벨업 보상 방향 섞지 않음 |
| C10 | 창 닫기/프로세스 종료가 의뢰 실패인가? vs 비정상 종료 저장 | **크래시는 전투 사망 아님**. 정상 종료/중단 재개·포기는 [미확정], 자동 이행 금지 |
| C11 | DB 출전은 복사인가? / 철수 후 자동 보관인가? | **보관→출전은 원본 이동, 성공 귀환도 수동 보관** [확정]. 회수/신규2개 한도 관계는 [미확정] |
| C12 | 원안 레이저·부메랑·추가탄 무한 출전 vs 탄환 하나의 형태 | 동일 빌드 가능해야 함. 합성 규칙 [미확정], 유실/무조건 배제 없이 프로토타입으로 비교 |
| C13 | '보스·구역 플레이 가능' 과거 보고 vs 체감상 동일 맵·동일 적·플러그인 부족 | 이전 완성 주장을 참조하지 않음. 5개 개성/실제 플레이 QA **새로 수행** |
| C14 | 과거 사용자 데이터 자동 마이그레이션을 전제로 한 문장 vs 최신 보호 정책 | **자동 이전 금지**, Python 5 JSON 보존·Unity 완전 별도 저장. 향후 명시 승인 때만 read-only import 고려 |
| C15 | 여러 UI 시안·이미지 중 8~12분 런/20~40분 런/40~60분 완주 혼재 | 확정: **하드웨어 당 8~12분**. 5개 완주 40~60분은 산술 추산·실측 전 초안 |
| C16 | 과거 Godot 엔진·경로·씬·CI 문서와 새 Unity 엔진 | Godot 지침은 원문에서만 보존, 신규 작업 지침에서는 삭제·대체 |
| C17 | 한때 사용한 60Hz fixed-step과 Unity 물리의 자동 결정론 가정 | 60Hz 게임 규칙 확정. 물리·플랫폼의 비트단위 동일성은 검증 전 주장 금지 |
| C18 | '보상 카드 최대 2개' 설명이 신규 의뢰 내 3장 중1 선택과 섞임 | **런 보상 화면 3장→1장**, **성공 철수 시 일반/레어 신규 학습 최대 2개**로 구분 |

## 5. 변경 관리

- 사용자가 직접 승인할 때 `D-xxx` 상태를 `approved`, 승인일, 정확한 선택, 영향 파일/테스트와 함께 바꾼다.
- **새 기획 아이디어**와 **이미 확정된 사용자 결정**을 같은 태그로 기록하지 않는다.
- 논의가 갈리는 사항은 기존 GDD v1 원문을 수정해 과거를 지우지 말고, 본문 v2와 결정 로그에 수정 사유/범위를 남긴다.
- 클로드 코드가 임의로 결정해야 할 때는 위험이 낮은 **시연용 임시값**만 두고 `Prototype`과 데이터 설정에 명시. 보상을 영구 저장하거나 백신을 파기하는 정책은 임시값으로 출시하지 않는다.
